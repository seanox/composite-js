## Reactive: Lifecycle Memory Diagnostic [reactive_lifecycle_memory_benchmark.html](reactive_lifecycle_memory_benchmark.html) keeps a reactive model alive while repeatedly creating, updating and removing views of 100 bindings. After 20 warmup cycles, it samples heap usage after each of five batches of 20 cycles, following DOM cleanup. Where available, `performance.memory.usedJSHeapSize` is reported in bytes with the difference from the warmup baseline. Otherwise the page explicitly reports that heap measurement is unavailable and still exercises lifecycle correctness. Memory output is separate from the runner's millisecond benchmark summary. These are browser-specific heap observations, **not a leak test or a pass/fail memory limit**. Samples may be coarse, include benchmark/runtime allocations and depend on when garbage collection runs. Neither growth proves a leak nor a stable sample proves its absence. For retention analysis, compare DevTools heap snapshots after garbage collection with the page still open and the model alive. Open this diagnostic on its own for memory investigations: heap samples can include other pages sharing the renderer, including the benchmark runner and previous iframe workloads.
